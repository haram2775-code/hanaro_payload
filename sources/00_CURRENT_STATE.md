## 1. 현재 개발 목적과 경계

### 1.1 작업 중인 임무 개념 — 승인 요구조건 아님

현재 개발은 다음 데이터 흐름을 검증하는 연구·시험 작업이다.

1. GPS/IMU와 기존 짐벌이 로켓 방향을 대략 지향한다.
2. Pi Zero 2 W와 Camera Module 3 Wide가 메인 로켓부의 약 10 ft 낙하산을 촬영한다.
3. 영상 알고리즘이 표적을 검출·추적하고 중심, 영상상 크기, 상태와 confidence를 계산한다.
4. 크기 변화와 자세 정보를 이용해 시선 방향 상대운동을 먼저 추정한다.
5. 카메라 보정, 짐벌·IMU 장착변환, 시각 동기와 페이로드 자체 수직속도가 확보된 경우에만 수직 상대속도 추정을 시도한다.
6. 추정 결과를 이용한 페이로드 낙하산 제어는 우선 SIL/HIL과 actuator 비활성 `SHADOW`에서만 검증한다.

영상으로 보는 표적은 **로켓의 약 10 ft 낙하산**이고, 제어 대상으로 검토하는 것은 **페이로드의 가변 낙하산**이다. 두 낙하산을 같은 부품이나 같은 크기로 취급하지 않는다.

### 1.2 현재 범위 밖 또는 별도 담당

- 짐벌 기구 전체 재설계, 낙하산 봉제·하중구조, 모터 선정, PCB·배터리 설계는 다른 파트의 주관 업무다.
- 필수 독립 회수장치는 영상, Pi, 통신, 실험용 제어기의 정상 동작에 의존해서는 안 된다.
- 비행 적용, 대회 제출, 외부 질의 발송은 이 문서 작성만으로 승인되거나 수행된 것이 아니다.

### 4.1 확인된 UART 범위

다음 결과는 OpenRB에서 Pi로 한 줄의 데이터를 보낼 수 있음을 확인한다.

```text
Pi port: /dev/serial0
Configured baud: 115200
Received: b'RB_ALIVE\r\n'
```

이 결과만으로 다음 항목은 확인되지 않는다.

- Pi→OpenRB 송신과 full-duplex 동작
- 실제 운용 길이·배선에서의 신호 무결성
- 장시간 packet loss와 재부팅 복구
- UART 논리 전압, 커넥터 방향, GND·역전원 안전성의 공식 대조
- CRC, sequence, heartbeat, timeout, timestamp 동기
- LoRa와 동시에 연결할 때의 포트 충돌 해결

OpenRB와 Pi/LoRa처럼 복수 장치가 통신해야 할 때 서로 다른 TX 출력을 한 RX 선에 직접 결선하지 않는다. 전용 하드웨어 UART, 검증된 multiplexer/bridge, 또는 다른 버스 중 하나를 전기 사양과 소프트웨어 소유권까지 포함해 선택해야 한다. 현재 선택은 미정이다.

## 5. 영상·상대운동 개발 상태

### 5.1 확인된 정의

- 표적: 메인 로켓부의 약 10 ft 낙하산.
- 제어 대상: 페이로드의 가변 낙하산.
- 중심 위치와 영상상 크기는 같은 mask에서 계산한다.
- 상태는 최소 `SEARCH`, `TRACK`, `OCCLUDED`, `CLIPPED`, `INFLATING`, `LOST`로 분리한다.
- 팽창·가림·화면 잘림에서는 크기 기반 거리·속도를 무효 처리해야 한다.
- 처리 FPS, 추정 출력률, 제어 명령률은 서로 다른 값으로 관리한다.

### 5.2 현재 해석 한계

영상상 크기 변화가 직접 제공하는 값은 시선 방향 접근률이다. 이를 수직 상대속도로 바꾸려면 카메라 내부 파라미터, 실제 투영 치수, 카메라–짐벌–IMU 장착변환, 자세, 페이로드 자체 수직속도와 공통 시각이 필요하다. 이 입력이 없으면 절대 거리·m/s를 확정 출력하지 않고 `접근/유지/이격`과 scale 변화율을 우선 사용한다.

약 10 ft라는 명목 직경도 모든 관측각의 유효 투영 치수가 아니다. drogue 단계에 해당 표적이 실제로 보이는지도 미확인이다. 따라서 main 전개 전 고속 구간의 검출·제어 가능성은 아직 주장하지 않는다.

### 5.3 KPI 상태

15–30 fps, 중심 메시지 약 10 Hz, 속도 메시지 1–2 Hz, capture→수신 p95 100 ms, 30 px 이상 recall 95%, 재포착 p95 1초 등은 **시험 시작값**이다. 현재 달성 실적이 아니며, 첫 독립 test 세트와 Pi 계측 결과로 수정해야 한다.

## 6. 낙하산·제어 모델 상태

| 항목 | 현재 값 | 분류 |
|---|---|---|
| 페이로드 낙하산 | 3 ft 가변 구조 | 모사 기준, 실물 확정 아님 |
| 독립 회수질량 | 1.0 kg과 2.2 kg이 과거 자료에 혼재 | 미확인. 두 값으로 민감도 분석 가능 |
| Cd | 0.97 사용 이력 | 가정. 해당 제품과 기준면적 정의 확인 전 확정 금지 |
| 제어 방향 | 속도를 늦추는 방향 중심 | 사용자 의도/연구안. 실제 기구의 재조임·양방향 가능성 미확인 |
| 모터 응답 | 값 없음 | 실측 필요 |
| 위치–CdA 관계 | 값 없음 | 실측 필요 |
| 고장 시 상태 | 독립 회수 우선 | 안전 원칙. 실제 기계적 구현 미확인 |

제어는 `이상적 정답 입력 SIL → 잡음·지연·누락 SIL → 영상 replay → Pi/OpenRB HIL → 제한 환경 시험` 순서로 검증한다. 위치, 장력, 전류, 이동시간, 캐노피 응답과 CdA의 실측값이 들어오기 전에는 안전거리나 braking TTC를 고정하지 않는다.

## 7. 대기·고도 분석 작업의 위치

ISA 기반 COTS 고도계 환산과 실제 대기 차이, 라디오존데 기반 고도 오차, OpenRocket용 대기 프로파일에 대한 별도 분석 이력이 있다. 현재 작업공간에는 6개 IGRA 계열 원시 관측소 ZIP이 제공되어 있다.

다만 이 상태 문서와 함께 제공된 자료에는 통합 보고서, 최종 수치표, 생성한 OpenRocket 프로파일과 재현 스크립트가 없다. 따라서 구체적인 고도 편차 수치는 이 문서에서 완료 사실로 승격하지 않는다. 해당 분석은 로켓 고도 예측과 COTS 계측 해석의 지원 트랙이며, 영상·낙하속도 제어 Gate를 직접 종료하지 않는다.

## 8. Gate 상태와 종료 조건

`07_FUTURE_DEVELOPMENT_PLAN_v3.0_VISION_DESCENT`의 Gate 체계를 현재 진행관리 기준으로 사용한다. 이전 `00_CURRENT_STATE`의 G0–G9 명칭은 이 표로 대체한다.

| Gate | 현재 상태 | 종료 조건 |
|---|---|---|
| G0 범위·가정 등록 | **미통과** | 10 ft 표적의 단계별 가시성, 독립 하강질량, 제어권, 규정 blocker, 담당자와 가정 범위 기록 |
| G1 데이터·광학 | 미통과 | 합성 GT, 독립 실영상 세션, 크기별 표본, intrinsics와 표적 실측치 |
| G2 검출·추적 | 미통과 | 독립 test 세트의 recall/FP/중심·크기오차/유효율/재포착과 실패 영상 |
| G3 상대운동 | 미통과 | LOS·수직 구분, 창·FPS별 오차/지연/불확실성, 팽창 invalid 검증 |
| G4 Pi 처리 | **부분 진행, 미통과** | 기록 단독·동시 처리 10분, 재부팅·vision restart, timing/drop/CPU/RSS/온도 로그 |
| G5 SIL | 미통과 | 질량·지연·phase·상실·공력 불확실성별 통과 영역과 제한조건 |
| G6 인터페이스·HIL | **UART 단방향만 확인, 미통과** | 프로토콜·공통 시각·양방향 loopback·fault injection·실시간 command 로그 |
| G7 공력·구동 인수 | 미통과 | 하중별 위치·장력·전류·이동시간, 위치–CdA–속도, 히스테리시스, 독립 해제 |
| G8 제한 환경 통합 | 미통과 | 승인된 범위의 제어하강·짐벌·상실·독립회수 시험 |
| G9 비행 여부 결정 | **NO-GO** | 최종 규정, ESRA 서면 해석, 독립 회수, G8 결과와 release 승인 |

Gate는 날짜나 코드 작성 완료만으로 통과시키지 않는다. G7에서 실물 응답값이 들어오면 G5와 G6를 다시 수행한다.

## 9. 규정·안전 경계

### 9.1 2026 첨부 문서에서 확인된 항목

- DTEG 6.1.1: 1,500 ft AGL 초과 독립 회수체는 apogee 부근 drogue/reefed main과 1,500 ft 이하 main/unreef의 dual-event CONOPS를 적용한다.
- DTEG 6.1.7: 회수 중 로켓 또는 페이로드의 어떤 부분도 GPS나 외부 센서 입력 등으로 guided되어서는 안 된다.
- DTEG 6.3.3: main 전개 시 drogue 하강속도는 20–40 m/s 범위다.
- DTEG 6.4.3 및 9.1.2.1: 착지속도는 11 m/s 미만이어야 한다.
- DTEG 9.1.2.2: 분리 회수 페이로드는 규정에 맞는 COTS GPS 추적기가 필요하다.
- DTEG 9.1.4: 로켓에는 독립 회수체가 최대 1개다.

### 9.2 2027 준비 상태

2026-09-29 ESRA 공식 문서 페이지는 2027 R&R·DTEG를 아직 WIP로 표시하고 2026 R&R v1.0 및 DTEG v1.1을 게시하고 있다. 2026-09-05의 2027 DTEG 사전 업데이트는 **guided recovery가 로켓과 페이로드 모두에서 계속 금지된다**고 명시한다.

따라서 영상·GPS·IMU 입력으로 페이로드의 하강 경로나 상대 위치를 능동 조절하는 비행 기능은 현재 `NO-GO`다. 지상 SIL/HIL, 제한시설 시험, actuator가 비활성인 관측·shadow 임무는 분리해 계속 개발할 수 있지만, 최종 2027 문서와 ESRA의 서면 해석을 다시 확인해야 한다.

공식 확인 경로:

- https://www.esrarocket.org/documents-and-forms
- https://www.esrarocket.org/news/dteg-updates

## 현재 판단

프로젝트는 Pi와 OpenRB의 기본 bring-up 일부를 완료했지만, 전체적으로는 `G0 범위·입력조건 등록` 단계다. 가장 확실한 진전은 Pi의 운용 기반, Camera Module 3 Wide의 단기 기록 이력, OpenRB→Pi UART 수신이다. 검출·상대운동 추정·실시간 처리·가변 낙하산·통합제어는 아직 완료 증거가 없다. 또한 2027 사전 규정에서도 guided recovery 금지가 유지되므로, 능동 낙하속도 제어를 비행 임무로 전제하면 안 된다.

## 다음 행동

`G0_INPUT_BASELINE.md` 한 장을 작성해 다음 네 항목을 담당자·확인일·근거와 함께 닫는다: ① 10 ft 표적이 보이는 회수 단계와 실제 형상, ② 페이로드 독립 하강질량과 3 ft 낙하산 실물 사양, ③ Pi–OpenRB–LoRa 포트·전원·제어권, ④ 비행 임무를 관측/shadow로 제한할지에 대한 팀 결정. 값이 없으면 임의 확정하지 않고 허용 범위와 blocker로 기록한다.

## 성공 기준

G0 표의 각 항목이 `확정값`, `허용 범위`, 또는 `담당자와 종료기한이 지정된 blocker` 중 하나로 분류되고, 그 결과가 `01_REQUIREMENTS_BASELINE.md`의 승인 대상으로 전달된다. 이후 첫 구현은 같은 기준을 사용한 WP1 데이터셋과 WP2 mask/중심/크기 로그로 시작할 수 있어야 한다.

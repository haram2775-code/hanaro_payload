## 1. 먼저 읽을 보고서

**하드웨어·회수 구성을 볼 때는 403 → 701 → 402, 본인 담당 영상 소프트웨어를 시작할 때는 604 → 407 → 314를 추천한다.** 401은 짐벌 지향·좌표계, 801은 하강 속도 계측과 기록 데이터 주입 시험을 위해 추가로 볼 만하다.

확인한 보고서 중에는 **다른 낙하체의 낙하산을 영상으로 추적하고, 겉보기 크기 변화로 상대속도를 추정하여 자기 낙하산의 하강 속도를 제어하는 전체 연결 구조**가 실증되었다고 확인할 수 있는 사례는 없었다. 따라서 아래 사례들은 각 개발 요소의 참고 근거이지 HANARO 전체 방식의 성능 보증은 아니다.

## 2. 조사 범위와 읽는 방법

- **2026 IREC Technical Reports 폴더만** 최종 분석에 사용했다. 처음 지정된 2025 폴더의 결과는 섞지 않았다.
- 요청한 36개 번호의 PDF가 모두 존재한다. **35개는 본문 보고서**, **503번은 외부 Google Drive 폴더 링크만 있는 1페이지 파일**이다. 503의 링크는 로그인 화면으로 연결되어 본문을 확인하지 못했다.
- 각 보고서의 개요, 페이로드 구성, 관련 항전·회수 계통, 시험·실패·향후 작업을 중심으로 읽었다. 전체 문서의 텍스트 검색을 병행하고, 텍스트가 추출되지 않는 402는 관련 페이지를 이미지로 읽었다. 모든 추진·구조 부록을 문장별로 완독했다는 의미는 아니다.
- 아래 **쪽수는 표지부터 센 PDF의 실제 페이지 번호**다. 문서에 인쇄된 페이지 번호와 다를 수 있다.
- '시험'은 보고서 작성 시점의 팀 자체 보고 내용이다. 대회 본비행 성공 여부를 별도로 확인한 것은 아니다. 목표, 시뮬레이션, 벤치 시험, 부분 비행 검증을 구분했다.
- 관련성은 첨부된 개발 계획을 기준으로 한 **분석 판단**이다. 문서 속 실행 지시를 따르거나 기존 계획을 수정한 것은 아니다. 기존 GPS/IMU coarse pointing, OpenRB 짐벌 제어권, Pi 영상·기록 역할을 유지하는 관점에서 비교했다.
- 다른 팀의 능동 회수 사례는 HANARO 2027 임무의 규정 승인 근거가 되지 않는다. 여기서는 해당 보고서가 설명하는 기술 구성만 비교한다.

## 4. 팀별 상세 요약

### 308 · University of Texas at Dallas · Persephone

**핵심:** 한 3U 안에 운동 계측과 진동 유도 발전 실험을 함께 넣었다. 약 4.4 lb의 비분리형 구조이며 알루미늄 프레임에 교체 가능한 선반을 넣는다.

- **구성:** Newton 계측계는 Teensy 4.1, 두 MPU6050, SD 저장장치와 독립 전원으로 운동을 기록한다. 별도 발전계는 자석·코일의 상대운동으로 전압을 만들고 ESP32와 microSD로 측정한다.
- **통합:** CAN/CANaerospace로 항전과 연결하고 텔레메트리와 기내 기록을 대조한다. 지상 소프트웨어·가상 CAN/MQTT 기반 에뮬레이션 설명도 있다.
- **해석:** 로켓의 시험 이력과 모든 과학 목표의 검증 완료를 동일시하지 않았다. 발전 출력이나 관성 추정 정확도의 완성된 비행 성능을 확인한 사례로 쓰기는 어렵다.
- **적용 판단:** WP6에서 센서 생성기·가상 수신기·기내 로그 비교를 준비할 때 참고. 동일 종류 IMU 둘을 평균내는 것 자체가 독립 정답값을 제공하지는 않는다.

근거: [보고서][308], PDF 25–27, 30–31쪽.

### 309 · University of São Paulo / Projeto Jupiter · Canarinho

**핵심:** 비행 중 대기 성분·환경 변화를 측정하는 약 4.73 lb의 3U 페이로드다. 기체에 고정된다.

- **구성:** SCD30 CO₂, MQ131 오존, SPS30 입자 센서, MPU6050, BMP280, 공기 유입용 팬. 알루미늄 프로파일과 모듈식 선반을 사용한다.
- **전자:** STM32 두 개가 측정과 통신·저장을 분담하고 UART로 연결된다. LoRa E22, SD·플래시, BMS와 전압 레일을 갖춘다.
- **해석:** 저속·고속 수집 모드의 주기가 제시되지만, 프로그램의 갱신 간격을 가스 센서의 실제 물리 응답속도와 동일시하면 안 된다. 브라질·미국 환경 비교는 임무 목표다.
- **적용 판단:** 센서별 갱신률·시간표시·데이터 보존 구조는 참고 가능하나 낙하산 영상·속도 제어와의 직접 연결은 낮다.

근거: [보고서][309], PDF 70–81쪽.

### 310 · Aeronautical University in Querétaro / SpaceDragons · Talavera

**핵심:** 약 2.5 kg 로버를 비행 중 기체에 보관하고, 착륙 확인 뒤 배출하여 지상을 탐사한다. 공중 독립 회수 로버와 구분해야 한다.

- **배출부:** Teensy 4.1, 복수 IMU·기압계, 상태 추정과 상태머신, 모터·엔코더 및 리드스크루로 배출한다. 배출 제어와 구동 전원을 분리한다.
- **로버:** 차동 구동, NEO-6M GPS와 MPU9250, EKF·Pure Pursuit 기반 이동. IMX219와 Luckfox Pico Zero로 장면을 작은 격자로 분류하고 압축된 정보를 XBee 링크로 보낸다.
- **검증:** 최종 배출·주행·무선 통합 확인 중 일부는 향후 작업으로 남아 있다. 전체 자율 임무의 비행 성공 사례로 볼 수 없다.
- **적용 판단:** 영상 원본과 저대역폭 요약정보를 분리하는 생각, 착륙 확인 후에만 구동하는 단계별 권한 관리가 WP4·WP6에 유용하다.

근거: [보고서][310], PDF 26–31, 34쪽.

### 312 · Federal University of ABC · Caipora-Amanã II

**핵심:** 바이오센서를 비행 환경에 노출하고 온도·압력·운동 기록과 연계해 지상 대조군과 비교한다. 약 2.5 kg, 3U이며 노즈 내부에 고정된다.

- **구성:** 2U는 단열된 바이오센서 용기, 1U는 전자부다. GY-91 계열 센서 모듈, microSD, 버저와 18650 전원을 설명한다.
- **해석:** 생물학적·센서 반응의 최종 결과를 제시한 보고서로 보기는 어렵다. 핵심은 노출 조건과 비행 전후 비교 설계다.
- **구분:** 별도 로켓 회수부에 reefing 해제가 나오지만 페이로드가 연속적으로 낙하속도를 제어하는 시스템은 아니다.
- **적용 판단:** WP1·WP7에서 동일 표적·동일 조건의 기준 데이터와 비행 데이터를 비교하는 실험 설계에 간접적으로 참고할 만하다.

- **적용 판단:** WP3·WP7에서 독립 계측값을 도입하되 측정 대상 물리량이 같은지 확인해야 한다는 비교 사례다.

근거: [보고서][703], PDF 33–35쪽.

### 705 · RMIT University · Horizon

- **적용 판단:** 여러 후보를 동일한 비행 환경에서 비교하는 시험 구성은 참고 가능하나, 영상·낙하속도 개발에서는 우선순위가 낮다.

근거: [보고서][705], PDF 25쪽.

- **미확인:** 페이로드 센서, 연산 보드, 전원·기록 구성, 구체적인 실험 목적과 결과. 문서에 없다는 이유로 무게추라고 단정할 수 없다.
- **적용 판단:** 장착·회수 하중 전달은 구조 참고가 가능하다. 현재 영상 소프트웨어의 벤치마크 대상으로는 정보가 부족하다.

### 707 · University of Calgary / SOAR · Aegis

**핵심:** 약 2.2 kg, 2U의 고정형 방사선 검출 실험이다. 섬광체와 SiPM을 사용하여 입자·감마선 이벤트를 측정한다.

- **구성:** BGO·BC408 섬광체 모듈, SiPM, STM32H747, ADC, IMU·기압·온도 센서, SD. 전원·주 제어·실험 보드로 나눈다.
- **비행 환경 대응:** 하강 중 방향이 바뀌는 점을 고려해 검출 모듈을 배치하고 외광을 차단한다. 센서 바이어스용 고전압과 논리 전원을 분리한다.
- **해석:** 계산된 배터리 운용시간과 실비행 검출 성능은 구분해야 한다. 최종 우주방사선 관측 결과를 제시한 것으로 보지 않았다.
- **적용 판단:** 센서 이벤트·환경·시간을 함께 기록하는 DAQ 설계에 간접 참고할 수 있다.

근거: [보고서][707], PDF 45–48쪽.

### 708 · University of Sydney · Rock Daisy

**핵심:** 3U 진공 챔버 안에서 모사 월면 토양 입자를 마찰 대전시키고 전기장으로 분리하는 실험이다.

- **검증:** 챔버·구조·액추에이터·벤치 시험을 보고한다. 입자의 편향은 관찰했지만 실제 분리 효율을 정량적으로 입증한 결과는 아직 부족하다. 일부 추가 검증은 미완료다.

- **적용 판단:** WP4·WP6에서 제어와 영상 기록을 분리하고 장애 직전 상태를 보존하는 구성은 참고할 만하다. 두 MCU를 그대로 도입할 필요는 없다.

### 709 · University at Buffalo / UB SEDS · SWEET

### 801 · Texas A&M University · Sol Invictus

**핵심:** 4U, 약 4.4 lb의 FMCW 레이더로 낙하산 하강 중 지면까지의 거리와 하강 속도를 측정하려는 실험이다.

- **구성:** RF 송수신·혼합·필터 회로와 안테나, FPGA의 고속 IF 샘플링, STM32 센서 보드, IMU·고가속도계·기압계·GPS, 플래시와 배터리.
- **소프트웨어:** 센서별 다른 샘플링률을 시간표시와 함께 기록하고 EKF 상태를 병행 계산한다. 정점 이벤트에서 레이더 파형 생성·FPGA 기록을 연계한다.
- **검증:** 실내 거리 변화 시험, 드론을 통한 필터 확인, 과거 비행 데이터를 센서 보드에 주입하는 시험을 설명한다. 보고서는 이를 SIL이라 부르지만 실제 보드가 참여하므로 HANARO의 SIL/HIL 정의로는 하드웨어 경계를 따로 적는 편이 정확하다.
- **중대한 제한:** 42쪽은 송신하지 않을 가능성을 설명하고, 50쪽 최종 운용 절은 주파수 관리 결정에 따라 IREC에서 송신하지 않는다고 명시한다. 따라서 모의 송신·기록 시퀀스가 동작해도 실제 레이더 거리·속도 측정 성공을 뜻하지 않는다. 예측 최대거리도 실증 거리와 구분해야 한다. 이는 해당 팀 보고서의 운용 설명이며 2027년의 일반 주파수 규정을 확인한 결과는 아니다.
- **적용 판단:** WP3·WP6·WP7의 관측량 정의, 시간동기, 재생 입력 시험에 좋다. 지면 기준 하강속도와 표적 낙하산 기준 상대속도는 서로 다른 물리량이다.

근거: [보고서][801], PDF 42–45, 50쪽.

## 5. HANARO 개발 항목에 연결하면

아래는 자료 비교에서 도출한 제안이며 기존 개발 계획을 수정·실행한 결과는 아니다.

| 개발 항목 | 우선 참고 | 가져올 내용 | HANARO에서 별도로 확보할 증거 |
|---|---|---|---|
| WP1 데이터·모사 | 701, 604 | 가시성 요구조건, 현장 영상과 데이터 품질 검토 | 완전 팽창/팽창 중/회전/가림의 상태 라벨, 촬영 조건, 거리·운동 GT |
| WP2 검출·추적 | 604 | 검출·분할 출력, 모델과 실행 파이프라인 분담 | 낙하산 전용 recall·오검출·동일 표적 유지·크기오차·재포착 |
| WP3 상대운동 | 701, 401, 801 | 형상 변화 관찰, 좌표계·상태 추정, 독립 운동 계측 | 크기 변화와 거리 변화 분리, LOS/수직 변환, 불확실성·invalid 판정 |
| WP4 Pi 처리 | 407, 314, 700, 406 | 실제 보드 운용, 기록/처리 분리, 단계별 기록, 로컬 보존 | Pi Zero 2 W에서 기록+추적 동시 처리, 지연·drop·열·전력·복구 파일 |
| WP5 제어 모사 | 403, 701, 709 회수부 | 줄 제어 개념, 캐노피 응답의 관찰, 실험과 모델 비교 | 자기 낙하산의 구동량–하강속도 관계, 지연·히스테리시스·포화 실측 |
| WP6 인터페이스 | 402, 501, 308, 801 | 연산/구동 책임, 시간 기준, 에뮬레이터·재생 입력 | Pi–OpenRB의 시간 변환, 데이터 나이, 중심/속도 메시지별 timeout |
| WP7 검증·인수 | 604, 403, 407, 603 | 실패에서 출발한 시험, 잡음 주입, 이중 경로 비교 | 독립 test 세트, 전원 상실·프레임 정지·잘못된 시각·표적 상실 시 결과 |

현재 계획에서 특히 유지할 가치가 큰 결정은 다음과 같다.

1. **녹화와 추론의 성공을 별도로 판정한다.** 604는 녹화 파일 손상, 407은 원하는 구간의 녹화 누락을 겪었다. 화면에 영상이 뜨거나 프로그램이 실행됐다는 사실만으로 원본 데이터 확보를 통과시키지 않는다.
2. **검출 FPS와 속도 추정 정확도를 분리한다.** 604의 실측·목표 차이가 이를 잘 보여준다. HANARO에서는 추적 주기와 속도 추정 창 길이·출력 주기를 따로 검증해야 한다.
3. **형상 변화가 있는 구간의 크기 관측을 그대로 거리 변화로 쓰지 않는다.** 701이 낙하산 팽창 영상을 별도로 확보하려는 이유가 WP3의 관측 한계와 연결된다.
4. **기존 제어권 구조를 유지하며 인터페이스를 명세한다.** 402·403은 기능 분담을 참고할 사례다. 그 팀의 MCU 종류를 따라 바꾸는 것은 본 비교의 결론이 아니다.
5. **HIL 통과와 실제 낙하산 동역학 검증을 구분한다.** 403의 잡음 주입 시험과 701의 관찰 장치는 서로 다른 불확실성을 줄인다. 가상 plant가 맞지 않으면 좋은 HIL 결과만으로 실제 하강 제어 성능을 보증할 수 없다.

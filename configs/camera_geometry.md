# 카메라 선정 · 관측 기하 · 연산 예산 (가정/설정값)

근거: 개발 공통 규칙 §1·§2·§3·§6, `configs/parachute_specs.md`, `configs/irec_conditions.md`.
수치는 **실측이 아닌 가정/설정값 + 제조사 확인 스펙**이다. 확정 임무 요구조건이
아니며, 절대 거리/m/s는 검증 없이 확정 출력하지 않는다(§6). 여기 값은 합성
시나리오 설계용이다.

## 1. 하강·분리 기하 (가정)
입력(사용자 제공):
- drogue 하강 속도 ≥ 20 m/s, main 하강 속도 ≤ 11 m/s.
- 페이로드 1.5 kg, 3 ft 낙하산 사용.

가정:
- 페이로드는 main(≤11 m/s)으로 저속 하강, 로켓 본체(자체 drogue 계열)는 ≥20 m/s로
  더 빨리 하강 → **상대 분리 속도 dv ≈ 20 − 11 = 9 m/s** (설정값).
- 분리는 main 전개 완료 시점(t=0)부터 선형 근사(초기 과도 무시). 실제 항력·과도는
  미확인이므로 선형은 **가정**이다.

| 경과 t (s) | 분리 거리 ≈ dv·t (m) |
|---|---|
| 0 | 0 |
| 2 | 18 |
| 5 | 45 |
| 10 | 90 |
| 20 | 180 |
| 30 | 270 |

## 2. 관측각(시선각) 범위 산정 (가정)
관측 기하 = **페이로드 탑재 카메라가 더 빨리 멀어지는 본체(+그 낙하산)를 올려다봄**.
- t=0: 본체가 바로 위(근접) → 캐노피를 **거의 정면(아래에서 위로)**, 시선 고도각 ≈ 80–90°.
- 분리가 커질수록 본체가 위로 멀어지며 시야에서 **각도가 낮아지고 작아짐** → 고도각이
  90°에서 점차 감소(예: 85° → 40°), 픽셀 크기도 감소.
- 반대 관측(지상 카메라가 하강 표적을 봄)이면 시선각이 **낮은 각에서 높은 각으로 증가**.

→ 시나리오는 **관측각이 시간에 따라 변하는** 것이 물리적으로 옳다. 본 구현은 표적별로
`view_elev_deg`(시작) → `view_elev_deg_end`(끝)로 **선형 보간**해 하강 중 각도 변화를 낸다.
기본 시나리오 범위(가정): **본체 관측 85° → 45°**, 지상 관측 30° → 70°.

## 3. 카메라 선정 (확정 스펙 + 사용자 가정 정정)
**선정: Raspberry Pi Camera Module 3 (Sony IMX708)** — Pi Zero 2 W 호환(공식),
autofocus, libcamera 지원.

출처: [Arducam IMX708 사양](https://docs.arducam.com/Raspberry-Pi-Camera/Native-camera/12MP-IMX708/),
[Raspberry Pi Camera Module 3 제품 페이지](https://www.raspberrypi.com/products/camera-module-3/) (확인 2026-09-29).

| 파라미터 | 확정값 | 비고 |
|---|---|---|
| 유효 해상도 | **4608 × 2592** px | 사용자 가정 "≈4000×3000"을 **실제 스펙으로 정정** |
| 광학 포맷 | 1/2.43″ (대각 7.4 mm) | |
| 픽셀 크기 | 1.4 µm | |
| FOV (표준) | 66°(H) × 41°(V), 대각 75° | 광각(102°) 버전 별도 존재 |
| 초점거리(픽셀) | **f ≈ 3548 px** | f = (W/2)/tan(HFOV/2), 표준 렌즈 기준 |
| 각분해능 | **≈ 0.25 mrad/px** (≈ 51.6 arcsec/px) | HFOV/W |

**정정 명시:** 사용자가 가정한 4000×3000은 IMX708 실제 유효 화소 4608×2592와 다르다.
계산은 확정 스펙(4608×2592)을 사용한다.

## 4. 표적 픽셀 크기 · 추적 가능성 (표준 렌즈, f≈3548px)
Main 캐노피 투영 지름 D=3.05 m(10 ft), Drogue d=0.91 m(3 ft). 픽셀 지름 = 2·atan(D/2R)·f.

| 사거리 R (m) | Main 픽셀지름 | Drogue 픽셀지름 |
|---|---|---|
| 50 | ~216 px | ~65 px |
| 100 | ~108 px | ~32 px |
| 200 | ~54 px | ~16 px |
| 400 | ~27 px | ~8 px |
| 800 | ~14 px | ~4 px |

추적 판정(가정): 유효폭 ≥ ~20 px가 안정 추적 하한. → **Main은 ~600 m, Drogue는
~200 m** 부근까지 표준 렌즈로 안정 추적 가능(가정). 그 이상은 광각 대신 망원(협FOV)
필요. 각분해능 0.25 mrad/px는 이 한계를 결정한다.

## 5. Raspberry Pi Zero 2 W — 1 fps 연산 예산 (설계 목표)
Pi Zero 2 W: 쿼드코어 Cortex-A53 @ 1 GHz, 512 MB RAM (제조사 스펙). **PC 처리시간을
클럭 비율로 환산해 Pi 성능으로 확정하지 않는다(§3).** 아래는 **1 fps 달성을 위한 설계
예산(가정)**이며 Pi 실측으로 검증해야 한다.

- **입력 다운스케일**: 4608×2592 원본을 프레임당 처리하면 1 fps가 어렵다. 검출/추적은
  **다운스케일 프레임(예: 1152×648, 1/4)** 에서 수행, 필요 시 관심영역(ROI)만 원해상도로.
  픽셀 수 1/16 → 연산 대폭 절감.
- **파이프라인 예산(1 fps = 1000 ms/frame, 가정 배분)**:
  캡처+다운스케일 ~150 ms · 세그멘트(색/임계) ~250 ms · 추적 업데이트 ~300 ms ·
  유효성 판정+기록 ~100 ms · 여유 ~200 ms.
- **연산 절감 원칙**: 무거운 딥러닝 추적기 대신 **색/형태 기반 세그먼트 + 경량 추적**
  (본 파이프라인의 fallback/CSRT 경로), ROI 국한, 프레임 스킵 허용.
- 이 예산은 **목표치**다. 실제 달성 여부는 Pi Zero 2 W 보드 실측(별도 Gate)으로만 확정.

## 6. 합성 반영
`Target.view_elev_deg_end`(및 `Stage`가 대상 Target에 위임)로 관측각을 시작→끝
선형 보간한다. mesh 백엔드에서 3D 자세로 반영되어 캐노피가 하강하며 기울어 보인다.
2D 백엔드는 눌림 계수로 근사한다. 기본값(end=None)이면 기존 고정각 동작 보존.
새 시나리오: `descend_view_body`(본체 관측 85°→45°), `descend_view_ground`(지상 30°→70°).
